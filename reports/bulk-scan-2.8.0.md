# 2.8.0 선택 라벨 스캔과 HTTP 범위 지정 오류 수정

## 재현과 수정

독립 Chrome 프로필에서 합성 CVAT를 `http://cvat-http.test`로 열었습니다. 이 호스트는 테스트 프로세스 안에서만 `127.0.0.1`로 연결하고 외부 DNS는 차단했습니다. 실제 회사 서버나 회사 라벨링 데이터는 사용하지 않았습니다.

브라우저에서 `isSecureContext === false`, `typeof crypto.randomUUID === 'undefined'`, `typeof crypto.getRandomValues === 'function'`을 확인했습니다. 수정 전에는 프레임 `1,3`의 대상을 확인할 때 사용자 화면과 같은 `crypto.randomUUID is not a function` 오류가 발생했습니다.

확인용 토큰 생성을 HTTP에서도 제공되는 `crypto.getRandomValues` 기반 128비트 난수로 변경했습니다. 보안 난수를 만들 수 없는 환경은 수정 없이 오류로 안내하며 `Math.random`으로 대체하지 않습니다. 기존 localhost 테스트는 Chrome의 안전한 컨텍스트 예외에 해당해 이 문제를 놓쳤습니다. 실제 확장 편집 통합 테스트를 일반 HTTP 호스트로 바꿔 같은 제한을 계속 검사합니다.

## 새 편집 흐름

검수 탭 안에 누락 검수와 삭제·라벨 변경을 유지합니다. 누락 프레임 가져오기 버튼은 제거했습니다.

1. CVAT 작업 저장 → 검수 → 삭제·라벨 변경.
2. 편집할 라벨 선택 → 선택 라벨 스캔.
3. 해당 라벨이 있는 프레임을 30개씩 확인. 라벨별 프레임 수와 Shape·Track 수도 표시.
4. 번호·구간(`3, 7, 20~40`) 또는 검색된 전체 선택.
5. 객체 삭제 또는 새 라벨 선택 → 대상 확인 → 확인 체크 → 적용.
6. CVAT에서 결과 확인·저장. 추가 편집은 다시 스캔.

스캔은 현재 Job의 CVAT 객체 내보내기를 읽어 계산합니다. 미저장 작업은 먼저 저장하도록 안내합니다. 읽은 주석은 페이지 메모리에만 유지하고 팝업·오버레이에는 라벨, 프레임과 개수만 반환합니다. 라벨 선택 변경은 화면의 스캔·확인 결과를 초기화합니다. 대상 확인은 같은 Job·라벨·스캔 토큰, 5분 유효시간, 주석·클래스 정보가 그대로인지 검증합니다. 적용 전에 다시 검사하고 실행 뒤에도 예상 결과와 대조합니다.

여러 라벨은 하나라도 있는 프레임을 중복 없이 표시합니다. Track은 Outside 구간을 빼고 존재 구간을 표시하며, 편집은 검색된 전체에서 Track 단위로만 허용합니다. Tag는 제외하고 Skeleton은 차단합니다. 잠금·보호·확인할 수 없는 객체의 기존 제한도 유지합니다. 삭제된 프레임에 객체 정보가 남으면 스캔 목록에 포함될 수 있으며, 실제 편집 대상을 읽지 못하면 적용하지 않습니다.

확장이 저장 버튼이나 서버 수정 API를 직접 호출하지 않습니다. CVAT 자체 자동 저장 설정은 계속 적용됩니다. 중간 실패는 일부 변경 가능성을 안내하며 자동 재시도하지 않습니다. 새 권한은 추가하지 않았습니다.
