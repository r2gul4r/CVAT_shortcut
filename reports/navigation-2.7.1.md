# 2.7.1 Job 이동 후 연결 상태 오버레이 복구

## 재현한 문제와 원인

2.7.0 코드와 별도 Chrome 프로필의 합성 CVAT에서 Job 12 → Job 99로 `history.pushState` 이동했습니다. 오버레이 연결 상태에 아래 오류가 표시됐고, 닫았다 다시 열어도 같았습니다.

```text
상태 확인 실패 / Job이 바뀌었습니다. 오버레이를 다시 열어주세요.
```

Chrome 메시지에서 읽은 `sender.url`은 `/tasks/1/jobs/12`였지만 실제 탭 주소는 `/tasks/1/jobs/99`였습니다. 같은 문서 안의 화면 이동 후 콘텐츠 스크립트 실행 환경의 최초 주소가 남은 경우입니다. 기존 워커는 이 주소의 Job과 현재 Job이 같아야 한다고 검사해 정상 요청을 거부했습니다. 오버레이를 다시 열어도 같은 콘텐츠 실행 환경을 사용하므로 해결되지 않았습니다.

추가 검사에서 새 Job의 연결 끊김 알림이 표시되지 않는 문제도 재현했습니다. 이전 Job 종료 때 알림 리스너를 정리한 뒤 다른 콘텐츠 메시지 핸들러만 남으면, 시작 메시지가 예외 없이 빈 응답으로 끝날 수 있습니다. 기존 코드는 예외가 났을 때만 리스너를 다시 삽입해 이 경우를 놓쳤습니다. 빈 응답 재주입 단위 검사도 수정 전 실패했습니다.

## 수정

- 메시지 발신자의 확장 ID·최상위 프레임·서버 origin을 확인합니다. 현재 탭의 주소와 요청의 Job을 대조하고 현재 최상위 문서의 실제 origin/path를 다시 읽습니다.
- Chrome이 문서 ID를 제공하면 발신 문서와 현재 문서 ID도 일치해야 합니다. 오래된 문서, 다른 프레임, 잘못된 Job·origin, 비활성 문서 요청은 계속 거부합니다.
- 문서 ID를 제공하지 않는 이전 Chrome에서는 현재 최상위 프레임의 실제 origin/path 검증을 사용합니다. 새 권한을 추가하지 않습니다.
- 연결 끊김·복구 이벤트도 같은 검증을 사용해 Job 이동 뒤 이벤트를 받아들입니다.
- 알림 시작 요청에 정상 준비 응답이 없으면 알림 리스너를 다시 연결합니다. 실패·빈 응답 모두 처리하며 초기화 재시도는 한 번입니다.
- 기존 수동·자동 모드 설정을 유지합니다. 수동은 새 Job에서 측정 시작을 누르고, 자동은 새 Job에서 다시 시작합니다. 이전 Job 통계는 새 Job과 합치지 않습니다.
- 검증은 현재 페이지 주소·문서 식별 정보만 읽으며 서버 점검 요청, 이미지 조회, 외부 전송은 추가하지 않습니다.

실패 0개. 재현 검사에는 다음 흐름을 포함합니다.

1. Job 12 → 99 이동 후 연결 상태 조회, 닫기 및 다시 열기.
2. 새 Job에서 수동 측정을 시작하고 실제 localhost 요청 1건을 집계.
3. 오버레이를 연 채 Job 99 → 42 이동, 자동 측정 재시작과 통계 초기화.
4. Chrome 네트워크 에뮬레이션으로 연결 끊김·복구 알림 확인. 추가 점검 요청 없음.
5. 작업 목록(`/tasks`)으로 나갔다 Job 77에 재진입해 오버레이와 자동 측정 복구.
6. 여러 Job을 이동한 후 검수의 네이티브 연결과 기존 일괄 편집 기능 확인.
7. 다른 문서·프레임·origin·Job과 이동 도중의 낡은 요청 차단.

모든 검사는 독립 Chrome 프로필과 합성 localhost 데이터를 사용했습니다. 실제 사내 CVAT나 회사 라벨링에 접근하지 않았습니다. 이전 2.7.0의 전체 744개를 모두 다시 실행한 결과는 아니며, 이번 변경과 관련된 검사 160개를 실행했습니다. 실제 설치된 CVAT와 구버전 Chrome은 별도 확인이 필요합니다.

## 적용

1. CVAT 작업을 저장합니다.
2. `chrome://extensions`에서 `C:\git\cvat_shortcut\extension` 로컬 확장의 **⟳**를 누릅니다. 폴더를 다시 등록하거나 확장을 삭제할 필요는 없습니다.
3. CVAT 페이지도 한 번 새로고침하고 확장을 켭니다. 팝업 버전 **2.7.1**을 확인합니다.
4. 오버레이 → 연결 상태를 엽니다. 자동 측정이 꺼져 있으면 측정 시작을 누릅니다.
