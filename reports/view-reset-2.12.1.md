# 2.12.1 회전 복귀 버튼 잠김 수정

## 확인한 문제

사용자 화면에서 5°가 표시되고 모든 회전 버튼이 비활성화되어 있었습니다. 기존 코드는 일반 회전과 0° 복귀에 똑같이 `busy`/fine rotation 지원 조건을 적용했습니다. CVAT가 도구·그룹·선택 상태이면 복귀도 막혔고, 이유가 긴 패널 하단에 있어 확인하기 어려웠습니다. 해당 회사 탭의 정확한 내부 mode 값은 직접 읽지 않았습니다.

## 수정

- 별도 `reset` 명령으로 CVAT의 public `canvas.cancel()`을 호출한 후 같은 Job·프레임, idle 상태를 재확인하고 0°로 돌립니다. 내부 mode 값을 강제로 바꾸지 않습니다.
- 기본 그리기/편집/그룹/선택 등의 취소 가능한 모드에서는 버튼을 활성화하고 **도구 취소 후 0°**라고 표시합니다. 미완성 그리기는 취소되며 기존 완성 객체는 수정하지 않습니다.
- 저장·로딩·재생·삭제 프레임·navigation block·실제 객체 드래그/크기 변경/회전 중에는 적용하지 않습니다. 취소 메서드 미지원, 취소 실패, 취소 중 Job/프레임 변경도 실패로 처리합니다.
- 1° 회전 어댑터가 지원되지 않는 경우에도 기본 0° 회전 경로를 확인할 수 있으면 복귀를 허용합니다.
- 비활성화 이유와 오류를 회전 버튼 바로 아래에 표시합니다. 일반 각도 변경은 기존대로 idle 상태에서만 허용합니다.

## 검증

- DOM 회귀: 572 통과 / 0 실패
- 화면 실제 MV3: 14 통과 / 0 실패
- 그룹 실제 MV3: 8 통과 / 0 실패
- 문맥 만료: 1 통과 / 0 실패
- 릴리스: 39 통과 / 0 실패
- 합계: 634 통과 / 0 실패

화면 DOM 검사 52개(전체에 포함) 중 신규 9개가 이 회귀를 검사합니다. 실제 MV3에서는 신뢰된 마우스 클릭으로 group mode에서 복귀, 미완성 스켈레톤 취소 후 복귀를 재현했습니다. 취소 실패가 angle을 바꾸지 않는지, 기존 완성 객체가 유지되는지, 저장·로드 차단도 검사했습니다.

회사의 실제 탭과 데이터 저장·재접속 검증은 하지 않았습니다. 화면의 내부 상태가 지원 조건과 다르면 이제 버튼 아래에 사유가 표시됩니다.
