# 수동 파일럿 안내 — 1.4.1

먼저 Windows 사용자 1명이 비기밀 테스트 작업으로 확인한 뒤, 소수 사용자에게 같은 버전을 전달해 피드백을 받는 방식으로 진행할 수 있습니다. Mac을 지금 테스트할 수 없다면 이번 파일럿은 **Windows 검증**으로 기록하고, Mac은 지원 확인 전으로 남겨주세요. 이 작업에서 파일을 다른 사람에게 보내거나 게시하지 않았습니다.

## 기존 CVAT 단축키와 겹치지 않게 정하기

1. **CVAT Settings → Shortcuts**에서 본인이 바꾼 키까지 확인합니다. 확장은 이 목록이나 사용자 설정을 자동으로 읽지 않습니다.
2. 두 기능에 쓸 **사용하지 않는 수정키+문자 조합**을 고릅니다. 단일 문자나 CVAT의 그리기/종료/삭제/프레임 이동/저장 키를 재사용하지 마세요. 공개 CVAT 기본키 예로 `N`, `Shift+N`, `G`, `M`, `Alt+M`, `Ctrl+R` 등이 있어, 이런 키를 겹쳐 쓰는 것은 피합니다. [공개 단축키 소스](https://github.com/cvat-ai/cvat/blob/develop/cvat-ui/src/components/annotation-page/standard-workspace/controls-side-bar/controls-side-bar.tsx)
3. Chrome/OS 예약 키도 피합니다. 팝업 경고는 예약 키의 충돌 가능성 안내이며 **CVAT 사용자 단축키 자동 탐지 결과가 아닙니다**. 경고가 없다는 것이 충돌 없음의 보장은 아닙니다.
4. 현재 키가 필요하면 확장이나 CVAT 설정 중 한쪽을 다른 키로 바꿉니다. 겹친 키를 우선순위로 해결하는 것을 배포 기준으로 삼지 않습니다.

## 충돌 처리의 실제 범위

확장이 지원되는 대기 상태에서 키를 받아 도구 호출을 처리하면, window 캡처 단계에서 기본 동작과 후속 이벤트 전파를 막습니다. 같은 물리 키를 계속 누르는 반복 이벤트와 정상 상태의 해당 키 release도 막아, 확인한 CVAT의 document 버블 단계 Mousetrap 핸들러가 같이 실행되지 않게 합니다. Ctrl/Shift/Alt/Cmd 자체의 release는 통과시켜 CVAT의 수정키 상태가 남지 않게 합니다.

이미 그리는 중이거나 편집 중인 경우, 입력칸/IME, 지원되지 않는 화면, 비활성/없는 도구에서는 새 도구 호출을 처리하지 않습니다. **이때 기존 CVAT 키 동작은 통과할 수 있습니다.** 따라서 겹친 키를 쓰면 대기 상태와 그리기 상태에서 다른 동작이 날 수 있습니다. 도구를 호출하려고 키를 처리한 뒤 클래스 확인 등이 실패하면 그 입력을 CVAT로 다시 보내지 않습니다. 입력/IME로 초점이 바뀐 release는 가로채지 않습니다.

window 캡처 단계에 확장보다 먼저 등록된 핸들러는 이미 실행됐을 수 있습니다. 그 핸들러가 preventDefault/stopPropagation으로 처리 표시를 하면 확장은 새 실행을 하지 않습니다. 표시 없이 먼저 실행한 동작은 되돌릴 수 없습니다. Chrome/OS가 키를 먼저 가져가거나, 다른 확장/포크된 CVAT가 이벤트를 다르게 처리하는 경우도 실제 확인이 필요합니다.

브러시 크기 휠은 활성 Brush/Eraser와 캔버스 위치 등 조건이 맞을 때만 Alt/Option 또는 Shift 이벤트를 처리하고, CVAT 캔버스 확대 및 후속 스크롤 핸들러 전파를 막습니다. 크기는 정규화된 한 단계마다 ±1입니다. 일반 휠, Ctrl/Cmd 휠·핀치, 캔버스 밖, 비활성 도구, 마우스 버튼을 누른 상태는 CVAT/브라우저 동작으로 통과합니다. OS의 실제 확대/제스처 결과는 가상 이벤트 검사만으로 확인할 수 없습니다.

## 각 사용자 체크 — 자작·비기밀 작업에서

- [ ] 설치/업데이트: 기존 확장 Reload → CVAT 탭 새로고침 → 팝업 Enable. 별도 설치는 설정도 별도입니다.
- [ ] Assign / Change / Clear / 팝업 다시 열기 및 중복 경고가 정상입니다.
- [ ] AI 키를 한 번 눌러 정확한 기본 클래스와 Interact 시작만 일어납니다.
- [ ] 새 마스크 키를 한 번 눌러 정확한 기본 클래스와 Shape 시작만 일어납니다.
- [ ] 키를 누르고 유지해도 추가 시작/종료/저장/프레임 이동 등 원래 CVAT 동작이 같이 나오지 않습니다.
- [ ] 키와 수정키를 놓은 뒤 정상 CVAT 키, 클릭, 이동이 동작합니다. 수정키가 눌린 상태로 남지 않습니다.
- [ ] 그리기/기존 마스크 편집 중 새 도구 키는 확장 실행을 하지 않습니다. 원래 CVAT와도 겹치지 않는 키인지 확인합니다.
- [ ] 라벨 이름을 없는 값으로 바꾸면 안내 후 실행을 멈춥니다. 원래 CVAT 키 기능이 대신 실행되지 않습니다.
- [ ] 텍스트 입력과 한글 조합 중 확장 실행이 없습니다.
- [ ] Alt/Shift 휠이 생성·편집에서 한 단계에 1씩 바뀌며 동시에 캔버스 확대/페이지 스크롤이 되지 않습니다.
- [ ] 일반 휠, Ctrl/Cmd 휠·핀치, 캔버스 밖 스크롤이 평소대로입니다. 마우스 버튼을 누른 중 크기 변경이 없습니다.
- [ ] 다른 사이트와 Pause 상태에는 확장 동작이 없습니다.

## 피드백 형식

확장 버전 / Windows·Chrome 버전 / CVAT 버전 / 테스트 항목 / 기대 동작 / 실제 동작 / 수정키 포함 재현 키 / 대기·생성·편집·입력 중 어느 상태인지 기록합니다. 회사 이미지·주석·URL·계정·인증정보는 포함하지 않습니다. 실패하면 팝업 Pause로 확장을 멈추고 같은 비기밀 테스트에서 차이를 확인합니다. 회사 데이터 화면을 외부로 캡처하거나 전송할 필요가 없습니다.

1.4.1 검증은 공개 Mousetrap과 모의 CVAT 컨트롤을 사용한 Chrome DOM 이벤트 검사입니다. 실제 회사 CVAT나 Mac에서 증명한 결과가 아닙니다. 개인 테스트에서 충돌이 없다는 피드백을 받은 뒤 파일럿 범위를 넓히세요.
